# Keep recordings tied to source truth

A diagram dataset and a site's catalog can land in separate changes. The book-notes site’s production bundle initially listed only shell fixtures, while the real Litefleet JSON already existed. Copy the real bundle to scratch and add the dataset entry only there. Retain the site SHA, dataset hash and explicit catalog-adaptation note. This demonstrates the actual UI without claiming production catalog integration is complete.

Use `git archive <pinned-commit>` to run source demonstrations without checking out or mutating another project. Extract code directly with `git show <commit>:<path>`, and check the scene's symbol and lines against that same object. A raw test log plus recorded terminal PASS makes a stronger evidence chain than an edited code card alone. Unit tests prove the behavior asserted by those tests, not the operation of the complete deployment.

Fixed pauses can end before subprocess output is visible on a busy VM. VHS supports `Wait+Screen /PASS/`; place its timeout setting at the top of the tape. Inspect an actual late frame from the recording, then retain the raw clip and describe any retiming. A successful VHS exit alone does not prove the application test succeeded. Independently run the command with its exit status checked.

Record timings from media probes, not the requested tape sleeps: terminal recording frames can differ from wall time under contention. Normalize and explicitly set scene playback rate from measured duration. For browser recording, close the Playwright context before saving the video. A Remotion scene need not share its source clip's duration.

The POC verification decodes the whole final MP4, checks H.264/720p/30fps/960 frames and the 10 MB ceiling, checks storyboard continuity and exact code extraction, and hashes all source clips. Visual inspection remains separate: full-graph Fit views are topology overviews at 720p, so carry the key path in a large callout and plan focus/zoom for a full build.
